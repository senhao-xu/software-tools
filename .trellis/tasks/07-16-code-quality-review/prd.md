# 审查代码质量与优化空间

## Goal

对仓库代码进行只读审查，识别有实际影响的缺陷、风险、测试缺口和可维护性问题，并给出可执行的优化建议。

## Background

- 仓库主体是 Go 编写的 `xsh` 集群部署工具，业务代码位于 `cmd/` 和 `internal/`。
- 当前工作区存在大量未提交改动，主要集中在 `.trellis/`、`.agents/`、`.claude/`、`.codex/` 和 `.opencode/`；目前未发现 Go 业务代码改动。
- 本任务只输出审查结论，不修改业务代码。

## Requirements

- 审查范围包含全部 Go 应用代码（`cmd/`、`internal/`）以及当前未提交的 Trellis/AI 配置改动。
- 审查结果以缺陷和风险为主，按严重程度排序。
- 每项发现包含文件和行号、影响、触发条件或证据，以及简洁的修复建议。
- 同时指出重要测试缺口和有明确收益的优化机会。
- 不把纯风格偏好或缺乏证据的猜测列为问题。
- 不修改被审查代码，也不覆盖或回退现有未提交改动。

## Acceptance Criteria

- [x] 明确本次审查范围。
- [x] 审查 `cmd/`、`internal/` 中的 Go 应用代码及其测试。
- [x] 审查当前未提交的 Trellis/AI 配置差异。
- [x] 运行适用的只读验证命令，包括 Go 测试、vet 和构建，以及配置侧已有的验证手段。（Go 工具链缺失，已记录阻塞。）
- [x] 输出按严重程度排序、带 `file:line` 引用的发现。
- [x] 若未发现明确问题，清楚说明残余风险与未覆盖的验证范围。

## Out Of Scope

- 未经用户另行要求，不实施修复或重构。
- 二进制产物、备份快照和纯生成副本不单独做风格审查；但若它们暴露发布、同步或仓库卫生风险，可以报告。
- 不在真实主机上执行会修改系统、安装软件或操作 Kubernetes/Docker 的端到端命令。
